# 4040 ROM-on-RP2040 investigation

## Current conclusion

The functional approach works in bounded host probes: the original, unmodified
4040 DOS 2.0 revision-2 ROM boots, interprets commands, owns channels and
filesystem state, and creates, writes and reads REL files. The production FIFO
RTL can bridge it without advancing GET for bytes merely queued to the PET.

Targeted full-board system tests additionally execute original PET KERNAL 2
and 4 OPEN/read calls through the soft PET CPU, PIA/VIA models, production FPGA
and physical SPI into the drive ROM and FILE-backed disk jobs. Independent
CPU-bus tests cover the RIOT and controller contracts rather than attempting
exhaustive DOS conformance at this layer.

This is not yet a core-0 feasibility pass or a complete compatibility result.
Manual RP2040 performance/DVI verification is deliberately the last step,
after simulation work. Host speed is not RP2040 throughput.
The investigation's scope explicitly excludes custom
6504 controller code (accepted by the operator), the second CPU, GCR
electronics, non-D64 formats, and devices 9-11.

## Experimental replacement

The branch replaces the C DOS/media/stream/channel implementation rather than
retaining it behind a switch. It supports device 8, drives 0 and 1, with exact
174848-byte, 35-track D64 images. D80, D82 and flat HDD support and their legacy
firmware suites are removed. Historical drive-development documents describe
the prior implementation, not this experiment. Shipped SuperPET configuration
no longer automatically mounts unsupported D80 images.

`fw/src/ieee/rom4040.c` uses the existing pinned
`test/external/chips/chips/m6502.h` submodule
(`264ddc2fe7a5127eeb0e87e44af6ca2314818706`). Its permissive license is
zlib/libpng, not MIT. The dependency is now required for firmware builds too.
BCD arithmetic remains enabled. No ROM instruction is patched, intercepted,
or replaced with a C filesystem routine.

The main CPU map follows schematic 320806, corroborated by MAME's
`c2040_main_mem`:

| CPU address | Storage |
| --- | --- |
| `$0000-$00FF` | Two 128-byte RIOT RAMs |
| `$0100-$01FF` | Aliases those RAMs, including stack |
| `$0200`, `$0280` and decoded mirrors | RIOT ports, DDRs, PA7 edges and timers |
| `$1000/$2000/$3000/$4000` | Four 1 KiB shared RAM blocks with 1 KiB aliases |
| `$D000-$FFFF` | Three original 4 KiB ROM chips |

A15 is not decoded. Native RAM is exactly 4352 bytes (4096 shared plus 256
RIOT). The whole machine structure is 4488 bytes in the ARM build and 4520
bytes on the 64-bit host, including independent RIOT edge/timer state.
The experiment additionally loads 12288 ROM bytes into SRAM from
SD, rather than redistributing or embedding the ROMs. The ARM
`m6502_tick` function occupies 14808 bytes of flash in the measured build.
These numbers exclude FILE/FatFs state, stack, transport and metrics.
The measured whole ARM firmware has 305332 bytes of text and 42160 bytes of
BSS. These are build observations, not a measured runtime stack margin.

`controller4040.c` supplies READ, WRITE, VERIFY, SEEK, BUMP and the recognized
stock formatter through the shared job/header/buffer interface. Geometry is
not filesystem policy. DOS owns BAMs, directory chains, allocation, names,
channels, status, EOF and REL. Exact I/O/flush failures become controller
results. The stock formatter is recognized against bytes in the original ROM,
not accepted as arbitrary code. Other controller execution fails explicitly.

Power-on executes the actual ROM diagnostics. The C controller acknowledges
the native controller wait-loop request, then publishes controller ID `$0F`
only after the last destructive shared-RAM test. Publishing it during the RAM
test causes the ROM to enter its LED error loop (observed during bring-up).

## FIFO ordering

`fifo4040.c` synthesizes a controller peer at the RIOT pins. It does not call
ROM subroutines directly or decode DOS commands.

- RX entries retain their ATN and EOI flags. Each head remains in the FPGA
  until the synthesized DAV/NRFD/NDAC exchange completes. ATN-release tokens
  are processed in the same queue order.
- A ROM DAV assertion offers exactly one byte for TX or TXS. Enqueueing it
  does not alter synthetic NRFD and does not permit ROM GET.
- The appropriate FPGA modulo-256 GET counter causes synthetic NRFD to fall.
  The ROM then reaches its actual `TLK30/GET`. The counter is reconciled before
  ATN, FIFO flush and source replacement. Single-byte offering makes counter
  wrap unambiguous (the RTL LOAD probe crosses wrap repeatedly).
- An unread termination instead raises NDAC while NRFD remains released, so
  native TLK20 aborts without GET. ATN can abort an unconsumed offer without
  losing the channel byte.
- Pausing prevents a new FPGA DAV, not completion of an already active byte.
  Firmware waits for active-byte protection and samples consumption again
  before processing a queued selection.

The 1024-byte FIFO cannot hide service gaps by speculatively running GET:
doing so changes channel and REL state before actual consumption. This
prototype deliberately has one outstanding ROM byte. That makes ordering
tractable but exposes per-byte SPI and core-0 scheduling cost.

## Reproduce the probes

Initialize the existing chips dependency and supply externally acquired ROMs:

```sh
# Restore the permissively licensed emulator dependency.
git submodule update --init test/external/chips

# Configure using a media directory whose roms/ contains the three chips.
export ECONOPET_MEDIA_DIR=/path/to/private/media
cmake --preset default

# Build Debug probe code with separately optimized Verilator model/runtime.
cmake --build --preset ieee-6502

# Verify all three SHA-256 identities, then run bounded probes.
ctest --preset ieee-6502 --output-on-failure
```

Required files are `roms/901468-14.bin`, `roms/901468-15.bin` and
`roms/901468-16.bin`. The runner checks them against
`tools/drive-roms/drive-emulation-roms.json`. Firmware additionally checks exact
chip sizes and published CRC32 values when loading them from SD.
ROM binaries are not tracked or redistributed. The original acquisition host
was unreachable in this environment, so inputs were obtained from VICE's
`data/DRIVES/dos4040-901468-14-16.bin` mirror and independently verified against
all three approved SHA-256 values.

The first probe executes real ROM bus cycles against a synthetic IEEE peer and
disposable memory-backed sectors. The second runs the production firmware
facade against the actual `ieee.sv` module in Verilator, injecting PET register
accesses and crossing the real Wishbone FIFO registers. This second probe is
not a full PET KERNAL or physical SPI integration test.

### Layered hardware contracts

`test/system/ieee/hardware4040_test.cpp` executes small instruction programs
through the production `rom4040_tick` bus decoder, not private memory-handler
calls. It checks RAM/stack/shared aliases, RIOT register mirrors, DDR/wired-DIO
composition, device straps, all ATNA/RFDO/DACO combinations, independent PA7
edge flags, and output-driven PA7 transitions. Timer tests measure all four
prescalers, the exact `1 + value * divisor` underflow boundary, free-running
post-underflow decrement, independent timer/edge acknowledgement and IRQ
wiring. RIOT0 flags cannot assert the main CPU IRQ or clear RIOT1 flags.
Every shared job slot is checked for its exact header, full-buffer boundary,
single callback and native result publication.

`rom4040_test.cpp` checks composition through the production FPGA and physical
SPI rather than duplicating that entire matrix at the slowest layer:

- Native boot, controller ID, both power-on BUMP results and SEEK/BUMP headers.
- Native M-W/M-R READ/WRITE/VERIFY, exact FILE-backed writes and error results.
- Two independently mounted drives with separate write/read/verify data.
- Native NEW downloads the actual stock formatter, clears raw media, builds
  the BAM and publishes the new ID through SEEK and subsequent sector reads.
- All 256 binary values traverse native LISTEN/PUT, disk WRITE, READ and
  TALK/GET, with exact received bytes and an independent wire/EOI trace.
  Listener batches stay below the FPGA's 32-entry RX depth and are serviced
  between batches (unserviced saturation correctly applies backpressure).
- GET-before-ATN and unread aborts, plus cold reset from idle, partial queued
  RX, unread DAV, consumed DAV and queued ATN. Every reset boots the original
  ROM and returns clean power-on/OK status without stale transport counts.
- Original PET KERNAL 2/4 OPEN/read, exact payload and per-byte KERNAL status,
  independently checked against wire observations.

This is exhaustive over the enumerated finite inputs, not every possible
instruction/event interleaving or physical timing. The C controller completes
jobs synchronously rather than reproducing rotational scheduling. Formatter
recognition and injected failures establish the raw-sector contract, not GCR
or arbitrary downloaded-code equivalence. The controller does not signal a
completion interrupt: native `TSTJOB`/`WATJOB` poll the shared job byte.
Cold-reset tests exercise `ieee_drive_reset`, not an independently driven
electrical IEEE IFC/reset circuit or the 6502 SO/NMI pins. No test establishes
analog RIOT fidelity or RP2040 performance.

### Independent RIOT agreement

`reference.riot_mame` executes the packaged MAME 0.264 MOS6532 implementation
out of process, on its Atari 2600 device with a synthetic self-looping
cartridge. No Commodore or Atari ROM is needed. Lua records actual register
observations without prescribing their values. A separate executable replays
those transactions through the production 6502 bus and RIOT implementation.
The run passes 16,544 nonempty masked comparisons from 16,584 bus reads
(zero-mask reads retain side effects but do not count as comparisons).

The comparison covers both ports, every DDR value, four latch patterns,
local port/DDR mirrors, both PA7 polarities and edge-control mirrors,
edge-flag acknowledgement, and stable timer load/reload/expiration flags
through all eight timer-load addresses. Board-specific input bits are masked
out because Atari and 4040 wiring differs. Output-driven PA7 still exercises
DDR-composed edge detection independently of the 4040 input adapter.

This is not independent agreement for external input wiring, IRQ wiring or
timer IRQ-enable state. Timer counters and timer-read acknowledgement are
not compared across different execution phases: MAME's Lua batches take
zero emulated time, whereas production replay executes CPU instructions.
In particular, a /1 timer can expire again between production accesses.
The finite CPU-bus tests above retain their exact timer and IRQ expectations.
The reference does not replace those tests or establish analog fidelity.

The runner validates every transaction's order, register, mask and write
value, requires an explicit completion record, and rejects missing, extra
or malformed observations. `reference.riot_integrity` tests those checks,
including an intentionally incorrect reference value against the executable.
Verbose output records the reference version and SHA-256 identities of its
binary, Lua script and observations rather than trusting a mutable emulator
version name alone.

Install MAME before configuring/building the system suite. Discovery includes
`/usr/games/mame`. If unavailable, configuration explicitly reports that
independent agreement is NOT tested and omits `reference.riot_mame`.
Passing the remaining suite or the integrity check is not independent RIOT
evidence. Require the actual comparison explicitly:

```sh
# Build the independent CPU-bus replay with the ordinary Debug system fixtures.
cmake --build --preset sys-test

# Fail if the independent comparison was not registered, rather than passing no tests.
ctest --test-dir build/system -R '^reference\.riot_mame$' --no-tests=error -V
```

### Independent original-controller agreement

The five `reference.controller_mame_*` scenarios execute the original 6504
controller ROM, RIOT/VIA, GCR PROM and floppy electronics in packaged MAME
0.264. After genuine DOS boot, the main CPU is parked with interrupts masked
and jobs are submitted through its shared-memory view. The controller CPU
and electronics continue running unmodified. A separate executable submits
the same jobs through actual production 6502 stores with persistent C
controller state. Completion, all eight header bytes and all 256 buffer bytes
are compared after each job. Both final disk images must match byte-for-byte.

The passing scenarios cover 174 jobs:

| Scenario | Jobs | Observations |
| --- | --- | --- |
| `normal` | 142 | Both drives, all 15 mailboxes, READ/WRITE/VERIFY/readback, zone boundaries, BUMP/SEEK, ID and verification failures |
| `protected` | 11 | Archive-backed read-only media, data jobs and stock formatter protection |
| `absent` | 10 | Missing drive 1, including successful media-independent BUMP |
| `errors` | 8 | Invalid track/sector, no-sync result and ID-before-sector error precedence |
| `format` | 3 | Original downloaded stock formatter, SEEK and readback, all 683 sectors and both final images |

These comparisons exposed and fixed missing header XOR publication, BUMP
rewriting its caller's header and incorrectly requiring media, wrong
invalid-track/error-precedence results, SEEK's physical header effects, and
the stock formatter's first/final header effects. The normal firmware suite
now retains fast regressions for those defects, not just system-level tests.

SEEK encounters a rotationally arbitrary sector. Each side must independently
return the correct ID and track, a legal sector and its correct XOR checksum.
Only that sector number and dependent checksum are normalized for comparison.
Every other header and buffer byte remains exact. No rotational scheduling
or original-drive speed-equivalence threshold is imposed on production.

MAME 0.264's D64 loader has a function-static sector descriptor initialized
with the first loaded disk's ID. It reuses that ID for subsequently loaded
images. These reference fixtures therefore use equal IDs but distinct data
patterns on the two disks. They establish independent drive/data routing,
not independent agreement for differing per-drive IDs. The finite production
hardware tests separately retain that contract.

The runner rejects missing, extra, malformed, out-of-order and incomplete
observations. `reference.controller_integrity` tests capture corruption and
the narrow SEEK normalization. Each run retains requests, native/production
observations, initial/final disks, logs and hash-bound `result.json` under
`build/system/controller-reference-artifacts/`.

```sh
# Build the CPU-mailbox replay alongside the ordinary Debug system fixtures.
cmake --build --preset sys-test

# Require all five native scenarios instead of silently passing an empty selection.
ctest --test-dir build/system -R '^reference\.controller_mame_' \
    --no-tests=error --parallel 2 --output-on-failure
```

### Protocol invariants and adversarial scheduling

The new histories use fixed seeds `1`, `$4040` and `$C0FFEE`, reported with
the failing request/attempt. Full-board cases also retain the simulator's
separate `ECONOPET_SIM_SEED`. These are reproducible adversarial schedules,
not an exhaustive exploration of all interleavings:

- Native listener tests send random payloads in random bursts of 1-16 bytes,
  schedule firmware at independently selected service periods, compare the
  complete input wire trace (including ATN and EOI), then CLOSE/reopen and
  require exact native-ROM readback.
- Native talker tests vary service periods, unread gaps and repeated service
  calls while stalled. They mix private data-register reads, unread ATN aborts,
  and real NRFD consumption immediately followed by ATN without intervening
  firmware service. An independent payload index and accepted-byte vector
  require exact bytes and final-byte EOI with no deletion or duplication.
- Offer conservation is checked at each byte and at completion:
  presentations equal accepted bytes plus unread aborts plus the single
  outstanding offer. GET advances only on actual consumption. Held offers
  cannot change presentation/consumption counts, and each seed must exercise
  both abort boundaries and finish within a finite retry bound.
- Persistent CPU/controller histories submit 64 randomized jobs per seed
  without resetting the controller between jobs. They vary job slots,
  drives, READ/WRITE/VERIFY, absent/protected media, wrong IDs, failed I/O,
  verification mismatches and CPU polling gaps. A separate image/memory model
  checks every shared-RAM byte and every media byte on both drives after
  every request, exactly one completion per submission, and no IRQ/NMI.
  Failures followed by later requests test recovery without stale ownership.

Run the histories with:

```sh
# Exercise production FPGA/SPI schedules and persistent controller mailbox histories.
ctest --test-dir build/system -R 'Adversarial/|SeededMailboxHistories' \
    --parallel 2 --output-on-failure
```

No rotational delay, mechanical schedule or original-drive speed-equivalence
threshold is introduced. Controller jobs still complete synchronously.
Service gaps are adversarial stimuli, not a requirement to slow the drive
to original hardware timing.

## Core-0 acceptance gate

Core 1 remains exclusively assigned to DVI. `ieee_drive_task` runs on the
existing core-0 main loop. Each pass is limited to 4096 emulated cycles and,
on RP2040, checks a 250 us service budget between 64-cycle slices. This is a
cooperative bound, not a hard deadline: an individual synchronous sector job,
especially formatting, can exceed it. Boot diagnostics are synchronous while
the PET is held during configuration/reset.
An outstanding source byte yields after one slice instead of repeatedly polling
SPI through the whole pass while the ROM is waiting for PET progress.

The UART CLI `drive` command reports cycles, calls, service time, elapsed
wall time, maximum service duration/gap, and presented/consumed counts.
The boot log also reports measured boot cycles/us. Read counters before and
after a fixed workload:

```text
effective service cycles/s = delta(cycles) * 1000000 / delta(service_us)
wall cycles/s = delta(cycles) * 1000000 / delta(elapsed_us)
```

Do not equate idle wall-cycle rate with useful payload throughput. Measure
actual PET LOAD/OPEN/CLOSE/REL completion times and deadline compliance while
DVI and USB are active, both with terminal rendering and in CLI mode.
`display_task` still performs synchronous video SPI and terminal output on
core 0. With one outstanding byte those gaps directly limit delivery speed.
No display throttling or extra-core migration has been used to hide this gate.

Acceptance still requires:

- RP2040 measurements of active ROM execution, per-byte SPI overhead and
  worst core-0 service gaps with DVI/USB/SD active.
- Additional native-reference comparisons beyond the passing KERNAL 2/4
  OPEN/read and GET-abort integration checks.
- Wider abort/partial-consumption permutations, listener backpressure and RX
  saturation with the ROM facade, and dual-drive/channel interleavings.
- Boundary REL records/side sectors, malformed/full media, write protection,
  failed I/O, reset/mount lifecycle and more command/directory operations.

RIOT ports, aliases, PA7 edges and timers are modeled. Error-map D64s,
mechanical timing, controller scheduling/retries
and raw GCR behavior are not modeled. Custom 6504 execution is accepted as
out of scope. ROM reuse removes the need to reimplement DOS semantics, but
does not itself establish that the C controller and virtual bus preserve every
observable behavior in the remaining compatibility target.

## Primary evidence

ROM source is `mist64/cbmsrc` commit
`01bd60f162ef92212ef0cb67546ae8f42be34168`, particularly `DOS_4040/master`,
`i_odef`, `ramvar`, `dskint`, `ieee`, `jobs`, `tsutil`, `memrw` and the
revision-2 overlays in the existing approval manifest. The archived source
alone is revision 1, not the selected binary.

The original IEEE routine is decisive: `TLK20` examines NRFD/NDAC, `TLK30`
calls GET, and `TLK35` waits for NDAC before releasing DAV/data/EOI.
MAME `c2040.cpp` at commit `9d8a6727a206fc822b8b69d67a51e6fd7dbf4d4b`
corroborates address aliases and `update_ieee_signals`.
`mos6530.cpp` at the same MAME revision corroborates the 6532 register decode,
timer divisors and underflow/read/IRQ behavior. Timer boundary tests are a
software-model contract, not an analog timing or real-chip measurement.
The selected ROM's `i_odef` and `ieee` bind the actual port/edge accesses.
VICE's high-level FDC was consulted for job-boundary corroboration only. No GPL source was
incorporated into the implementation.
